## 📌 Самая короткая версия (для быстрого возвращения в работу)

- Сайт собирается из обычных текстовых файлов программой **Eleventy**. Получается набор готовых HTML-страниц, который бесплатно раздаёт **GitHub Pages**.
- **`.md` файлы — это КОНТЕНТ** (текст, который видят люди).
- **`.njk` шаблоны — это РАЗМЕТКА** (каркас: карточки, шапка, меню).
- **`style.css` — это СТИЛЬ** (цвета, шрифты, отступы).
- Единственное, что вы делаете вручную, — **пишете контент в `.md`** и нажимаете «Sync». Всё остальное (сборка и публикация) делается автоматически.

**Весь рабочий цикл:** правите текст → «Sync» → подождали ~1 минуту → сайт в интернете обновился. 🚀

## 1️⃣ Что это за сайт и из чего состоит

### Слои сайта (главная идея)

Представьте сайт как трёхслойный пирог:

```
┌─────────────────────────────────────────────┐
│  🎨 СТИЛЬ  — style.css                      │  КАК выглядит
│     (цвета, шрифты, размеры, отступы)        │
├─────────────────────────────────────────────┤
│  🧱 РАЗМЕТКА — шаблоны *.njk                │  ГДЕ что размещено
│     (карточки, заголовки, списки, меню)      │
├─────────────────────────────────────────────┤
│  📝 КОНТЕНТ — файлы *.md                    │  ЧТО написано
│     (тексты статей, законов, разделов)       │
└─────────────────────────────────────────────┘
```

Почему так удобно:
- Чтобы поменять **слова** — правите только `.md`. Разметка и дизайн не трогаете вообще.
- Чтобы поменять **внешний вид** (например, цвет кнопок) — правите только `style.css`, и это меняет сразу весь сайт.
- Чтобы поменять **структуру** (добавить тип карточки) — правите один шаблон `.njk`, и он применится ко всем страницам этого типа.

### Кто всё склеивает

Между вашими файлами и готовым сайтом стоит программа-**сборщик** **Eleventy**. Она:
1. Берёт каждый `.md` файл (контент) и его «шапку»-настройки (frontmatter).
2. Вставляет контент в нужный шаблон `.njk` (разметку).
3. Соединяет с общим каркасом (шапка-меню-подвал).
4. Выдаёт готовые HTML-страницы в папку `_site/`.

`_site/` — это и есть сайт. Его-то и показывает GitHub Pages.

```text
│   │   └── page.njk                   → рамка карточек (О нас, Контакты)

│   ├── 🗂️ _data/                      → общие данные для всего сайта

│   └── 🖼️ doc/                        → картинки и PDF (Устав, логотип)
│
├── 🏗️ _site/                          → ГОТОВЫЙ САЙТ (его строит Eleventy) — НЕ ТРОГАТЬ
├── 🗄️ _backup/                        → архивные копии для отката
├── 📦 node_modules/                   → программы-сборщики — НЕ ТРОГАТЬ
├── 💡 ПАМЯТКА.md                      → этот самый файл
└── ⚙️ .eleventy.js                    → настройки сборщика (меняем редко)
```

Что важно понять из карты:

- **`src/` — ваш «рабочий стол».** Всё, что вы создаёте и правите, лежит внутри. Ничего за его пределами трогать не нужно.
- **Три «Р»:** папки `_includes` (разметка), `_data` (данные) и `doc` (картинки) служат помощниками. В них заглядываем редко — обычно только чтобы что-то поправить разово.
- **`_site/` и `node_modules/`** — это «продукция» и «инструменты», их создаёт и заполняет программа. Руками туда не заходим.

### ⚠️ Золотое правило
> **Правим только папку `src/`. Папки `_site/` и `node_modules/` не трогаем никогда** — их создаёт программа.
>
> Если исправили файл, а сайт не изменился, — проверьте, что правили в `src/`, а не в `_site/`.

- **Шапка страницы** (название, описание, мета-теги для поисковиков и соцсетей) — собирается из настроек файла.
- **Активный пункт меню** — подсвечивается по полю `active`.
- **«Содержание»** в законах и обзорах — строится из заголовков.
- **Реквизиты** (адрес, телефоны, ИНН) — заданы один раз в `site.json` и подставляются по всему сайту.

## 5️⃣ Как устроен `.md` файл и что за «шапка»

Каждый `.md` файл имеет две части:

```markdown
---
layout: article.njk        ← ШАПКА (frontmatter): настройки и данные
title: "Название статьи"
subtitle: "Подзаголовок"
description: "Описание для поисковиков"
active: articles
---

## Первый заголовок

Текст статьи... **жирное слово** и *курсив*.

- пункт списка
- ещё пункт
```

- **`---` ... `---`** — блок «шапки». Это данные: какой шаблон использовать, заголовок, описание, подсветка меню.
- Всё **после** второй `---` — сам текст. Здесь работают значки: `##`, `**`, `- `.

### Быстрый справочник значков (для текстов)

| Хочу | Пишу | Результат |
|---|---|---|
| Заголовок раздела | `## Название` | крупный заголовок |
| Подзаголовок | `### Название` | заголовок поменьше |
| Жирный текст | `**важно**` | **важно** |
| Курсив | `*акцент*` | *акцент* |
| Маркированный список | `- первый` | список с точками |
| Нумерованный список | `1. шаг` | список с номерами |
| Ссылка | `[текст](адрес)` | кликабельный текст |
| Цитата | `> мысль` | выделенная цитата |
| Пустой абзац | пустая строка | новый абзац |

Подробная памятка по правилам markdown лежит прямо на сайте:
**https://ligazpp.github.io/articles/markdown-memo/**

## 6️⃣ Два вида страниц: «чистый текст» и «комбо с элементами»

Главный практический вопрос при создании страницы: **сможет ли я написать её целиком на простом `.md` или понадобится ещё разметка?** Ответ зависит от того, что будет на странице.

### Вариант А — «чистый текст» (классика, самое привычное)

Это когда страница — просто текст + заголовки + списки + ссылки. Идеальный случай для чистого `.md`:

```markdown
---
layout: article.njk
title: "Как вернуть товар"
active: articles
---

## Куда обращаться

Обычный текст, списки, **жирное**, [ссылки](#).

- пункт 1
- пункт 2
```

**Когда подходит:** блог-статьи, разборы законов, любые «сплошные» тексты. Вы просто пишете — сборщик сам превратит значки в готовый HTML.

### Вариант Б — «комбо»: текст + интерактивные элементы

Когда на странице есть «фишки» — **аккордеон (FAQ), карточки с иконками, формы, выпадающие списки, картинки-галереи** — чистый `.md` уже не справляется: у markdown нет «синтаксиса» для таких элементов. Тогда страницу делаем гибридом:

- 📝 **Текст** — по-прежнему в `.md` (шапка + markdown-тело).
- 🧱 **Элементы** — либо штатными блоками шаблона `.njk`, либо вставкой готового HTML-кусочка прямо в текст.

Пример «комбо» уже есть на сайте — страница **«Потребителю»** (`src/consumer.njk`). Её FAQ — это не текст в `.md`, а **аккордеон**: блоки с вопросами-заголовками, которые раскрываются кликом. Такое чистой разметкой не наберёшь — нужен HTML + маленький скрипт (он уже в `script.js` и менять его не нужно):

```markdown
<div class="faq-item">
    <div class="faq-question">Вопрос пользователя</div>
    <div class="faq-answer" hidden>Развёрнутый ответ</div>
</div>
```

Аналогично **«О нас» и «Контакты»** — это тоже «комбо»: текст карточек лежит в шапке (секция `cards:`), а сами карточки-плашки с иконками рисует шаблон `page.njk`.

### Как выбирать — простая шпаргалка

| Что на странице | Какой подход |
|---|---|
| Только текст, заголовки, списки, цитаты | ✅ Чистый `.md` |
| Вопрос-ответ с раскрытием (аккордеон) | 🧱 «Комбо»: маленький HTML-блок |
| Карточки-плашки с иконками | 🧱 «Комбо»: шаблон `page.njk` |
| Картинки в тексте | ✅ Чистый `.md` (строчка `![подпись](путь)`) |
| Форма обратной связи | 🧱 «Комбо»: HTML-форма + внешний сервис приёма писем |
| Выпадающие списки / вкладки | 🧱 «Комбо»: HTML + готовый скрипт |

**Практический совет:** почти всегда начинайте с Варианта А — чистого `.md`. Он проще, надёжнее и его легко читать и через год. «Комбо» подключайте только если без интерактива никак не обойтись, и лучше спрашивайте — я подскажу, как это правильно встроить.

> Нюанс про формы: сайт статический, «сам» письма принимать не умеет (нет бизнес-логики на сервере). Обычно форму подключают через бесплатный внешний сервис-посредник (например, Formspree) — это решаемо, но выходит за рамки простого `.md`.

## 7️⃣ Образец промта для нейросети (DeepSeek)

Скопируйте текст ниже, замените `{ТЕМА}` на свою тему — и получите готовый `.md`-файл, который останется только сохранить и проверить.

```
Ты — редактор общественной организации «Лига защитников потребителей».
Напиши статью для сайта лиги по теме: {ТЕМА}.

ФОРМАТ ВЫВОДА — строго Markdown, готовый файл для переноса на сайт:

---
layout: article.njk
title: "Название статьи"
subtitle: "Короткое описание под заголовком"
description: "Краткое описание для поисковых систем (1–2 предложения)"
active: articles
---

   (далее сам текст статьи)

Правила оформления:
- Заголовки — только значки ## (раздел) и ### (подраздел). Заголовок первого уровня # не использовать.
- Абзацы отделяются ПУСТОЙ строкой (Enter дважды).
- Жирный — **важные термины и выводы**, курсив — *акценты*.
- Списки — строки с "- " (маркированный) или "1. " (нумерованный) для шагов.
- Цитаты — строки с "> " для важных правовых мыслей.
- Внутри текста НЕ использовать: таблицы, HTML-теги, картинки, смайлики.

СТИЛЬ: живой, дружелюбный, уверенный, понятный обычному человеку —
без канцелярита и панибратства, без занудства. Сложное объясняй простыми словами.

СТРУКТУРА:
1. Короткое вступление — зачем читать.
2. Разделы с полезными подзаголовками (## и ###).
3. Пошаговый алгоритм действий — что делать, куда обращаться, что говорить.
4. Учитывай, что продавец может отказывать или путать покупателя — заранее
   дай ответы на такие ситуации.
5. Списки и риторические вопросы.
6. Краткий мотивирующий вывод в духе: «закон на вашей стороне — Лига поможет».

ЦЕЛЬ: правовое просвещение и практическая помощь гражданам.
Объём — примерно 1000–1500 слов. Верни только сам файл .md без пояснений.
```

Как пользоваться готовым результатом:

1. Скопируйте ответ нейросети.
2. В VS Code создайте файл `src/articles/имя-статьи-латиницей.md`.
3. Вставьте текст, проверьте шапку (frontmatter) и пустую строку после неё.
4. Следуйте контрольному списку ниже (не забудьте карточку в `articles.njk`!).

## 9️⃣ Как опубликовать изменения в интернете

### Способ 1 — кнопками (самый простой) 🖱️

1. Сохраните правки: **Cmd + S** (на Mac).
2. Слева нажмите иконку **Source Control** (тройная веточка).
3. Убедитесь, что ваши файлы видны в списке **Changes**.
4. Впишите сообщение (например «обновил статью») и нажмите **Commit**.
5. Нажмите **Sync Changes**.
6. Через 1–2 минуты сайт обновится. 🟢

### Способ 2 — командами в терминале

```
git status                — показать, какие файлы изменены
git add .                 — отметить все изменения
git commit -m "что изменил" — сохранить снимок (свой текст в кавычках)
git push                  — отправить на GitHub (публикация запустится сама)
```

> Если `git status` пустой — вы правили не тот файл. Правки должны быть в `src/`.

---

## 🔟 Что происходит после «Sync» (автоматически)

1. Изменённые файлы попадают из VS Code на GitHub.
2. «Робот-сборщик» (GitHub Actions) сам:
   - ставит программу Eleventy,
   - собирает сайт из исходников → папка `_site/`,
   - выкладывает готовый сайт на GitHub Pages.
3. Люди получают обновлённую страницу на https://ligazpp.github.io.

**Ваша работа — только шаг 1 (поправить текст и нажать Sync).** Сборку и публикацию вы руками не делаете.

---

## ▶️ Как проверить, что всё опубликовалось

1. Зайдите на GitHub в репозиторий **ligazpp/ligazpp.github.io**.
2. Откройте вкладку **Actions**.
3. Если последняя сборка **зелёная** — всё хорошо, сайт обновлён.

## 🤔 Может возникнуть вопрос: «Это надёжный и правильный подход?»

Да. Это стандартная технология **статических сайтов** (используется повсеместно). Преимущества для такого сайта:

- 💰 Бесплатно (не нужен платный хостинг).
- ⚡️ Очень быстро грузится (готовые HTML-страницы, без сервера).
- 🔒 Безопасно (нечего взламывать, нет базы данных).
- 🧘 Не требует ничего продлевать и обновлять годами.
- 📄 Контент — обычные текстовые файлы, их легко копировать и бэкапить.

PHP/WordPress в этом сравнении дали бы удобную «админку с кнопками», но потребовали бы платный сервер, базу данных, обновления и больше земли под уход. Для информационного сайта Лиги статический подход — оптимальный.
