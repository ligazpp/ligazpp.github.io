## 🧱 Как всё устроено (простыми словами)

**Аккаунт на GitHub (ваш вход в сайт github.com) — это `zppliga`.**
Он — «хозяин» и администратор всего. Внутри аккаунта создана **организация `ligazpp`** — отдельный «кабинет» для сайта.

В организации живёт **один репозиторий**:

- 📁 **`ligazpp.github.io`** — в нём лежат исходники сайта.

**GitHub Pages работает по простому правилу:**
> Если репозиторий называется `что-то.github.io`, GitHub сам открывает сайт по адресу `что-то.github.io`.

Поэтому наш репозиторий называется именно `ligazpp.github.io`, и сайт открывается на **https://ligazpp.github.io**.

**Важно:** в репозитории хранятся **исходники** (тексты, стили, настройки), а не готовые страницы. Готовый сайт из них собирает GitHub автоматически — ничего руками собирать не нужно.

### Одна схема

```
✍️ Вы правите тексты в VS Code (папка src/)
        │
        ▼
📤 Commit + Sync — изменения уходят в репозиторий ligazpp.github.io
        │
        ▼
🤖 GitHub «робот» (Actions) собирает сайт из исходников
        │
        ▼
🌍 GitHub Pages выставляет готовый сайт
        │
        ▼
👀 Люди открывают https://ligazpp.github.io
```

Шаги 2–4 выполняются сами. Ваша работа только в шаге 1.

## 💾 Два способа опубликовать изменения

### Способ 1: кнопками (самый простой)

1. После правок нажмите **⌘S** (сохранить).
2. Слева нажмите иконку **Source Control** 🪵 (три веточки).
3. Убедитесь, что видите свои файлы в списке «Changes».
4. Впишите сообщение (например: «обновил статью») → **Commit**.
5. Нажмите **Sync Changes** (синяя кнопка).
6. Готово! Через ~1–2 минуты сайт обновится.

### Способ 2: командами в терминале VS Code

Откройте терминал: меню **Terminal → New Terminal** (или клавиша ``Ctrl+` ``), затем по порядку:

```bash
# 1. Показывает, какие файлы вы изменили
git status

# 2. Отмечает все изменения к отправке
git add .

# 3. Сохраняет «снимок» с пояснением (своё сообщение в кавычках)
git commit -m "что я изменил"

# 4. Отправляет на GitHub — публикация запустится сама
git push
```

Если после `git status` выше список «ничего не изменилось» — вы правили не тот файл. Ищите правки в папке `src/`, а не в `_site/`.

## 👀 Предпросмотр на компьютере (до публикации)

Всё тот же терминал:

```bash
npm run dev
```

Откройте в браузере **http://localhost:8080** — это ваш сайт «как есть», но только у вас на компьютере. Остановить: нажмите **Ctrl+C** в терминале.

## 📁 Где лежат ваши тексты

| Куда смотреть | Что находится |
|---|---|
| `src/articles/*.md` | статьи и материалы (один файл = одна статья) |
| `src/*.njk` | тексты разделов: Начало, О нас, Контакты |
| `src/style.css` | внешний вид (цвета, меню, отступы) |
| `src/script.js` | поведение (мобильное меню, кнопки) |
| `src/_data/site.json` | контакты, реквизиты, соцсети |

**Главное правило:** правим **только `src/`**. Папки `_site/` и `node_modules/` не трогаем — их создаёт программа.
